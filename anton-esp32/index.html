Executive summary

ESP32를 붙이면 무엇이 달라지는가?

SPIKE Prime은 LEGO 생태계 안에서는 매우 편리하지만 일반 전자부품의 GPIO, I2C, UART, BLE 장치를 자유롭게 연결하기 어렵습니다. LMS-ESP32가 이 경계를 연결합니다.

01

센서 확장

HuskyLens, 라인센서, 음성인식 센서 등 일반 I2C/UART 센서를 SPIKE 프로젝트에 포함할 수 있습니다.

02

출력 확장

서보, NeoPixel 등 LEGO 포트 밖의 액추에이터와 LED를 ESP32에서 제어할 수 있습니다.

03

무선 입력

BluePad32/BT 계열을 이용해 PS4·Switch 계열 게임패드나 모바일 RC 입력을 연결할 수 있습니다.

04

역할 분리

AI·통신·센서 전처리는 ESP32, 주행 판단과 LEGO 모터 제어는 SPIKE가 맡는 분산 구조가 가능합니다.

Core technology

PUPRemote: ESP32를 LEGO 센서처럼 보이게

가장 중요한 라이브러리입니다. ESP32 측의 PUPRemoteSensor와 허브 측의 PUPRemoteHub가 대응하며, 채널 또는 명령을 정의한 뒤 값을 읽거나 호출합니다.

저수준: LPF2 에뮬레이션

ESP32가 LEGO Powered Up 장치 프로토콜을 흉내 냅니다. SPIKE 허브의 포트에서 외부 MCU를 '센서'처럼 다룰 수 있게 하는 기반 계층입니다.

상위: RPC 스타일 호출

명령 이름과 struct 포맷을 정의하고, SPIKE에서 call()을 사용해 ESP32 함수를 호출하는 식으로 빠르게 프로토타입을 만들 수 있습니다.

LMS-ESP32 · main.py — 최소 PUPRemote 예제
from pupremote import PUPRemoteSensor, SPIKE_ULTRASONIC

value = 0

def num(*argv):
    global value
    value += 1
    return 2 * value, -3 * value, 4 * value

p = PUPRemoteSensor(
    sensor_id=SPIKE_ULTRASONIC,
    power=True,
    max_packet_size=16
)

p.add_command(
    "num",
    from_hub_fmt="3b",
    to_hub_fmt="3b"
)

while True:
    p.process()
SPIKE Prime · Pybricks — ESP32 명령 호출
from pybricks.parameters import Port
from pupremote_hub import PUPRemoteHub

p = PUPRemoteHub(Port.A, max_packet_size=16)

p.add_command(
    "num",
    from_hub_fmt="3b",
    to_hub_fmt="3b"
)

result = p.call("num", 1, 2, -45)
print(result)
Pybricks 패킷 주의: Anton의 PUPRemote 문서는 Pybricks에서 32-byte 패킷 관련 제약이 있을 수 있어 max_packet_size=16 사용을 권장하는 호환성 메모를 제공합니다.
Getting started

실습 시작 순서

처음부터 HuskyLens까지 한 번에 연결하기보다 통신 계층을 단계별로 확인하면 디버깅이 쉬워집니다.

1. LMS-ESP32 펌웨어 설치

Anton firmware installer에서 프로젝트에 맞는 펌웨어를 플래시합니다. 일반 학습용 시작점은 MicroPython 1.25.0입니다.

2. ViperIDE 또는 MicroPython IDE에서 ESP32 확인

REPL 접속과 간단한 print가 정상인지 확인하고, 필요한 라이브러리가 펌웨어에 포함되어 있는지 확인합니다.

3. PUPRemote 더미 데이터 통신

외부 센서를 연결하지 않고 숫자/문자열을 ESP32 ↔ SPIKE로 먼저 주고받습니다.

4. 실제 I2C/UART 센서 연결

HuskyLens나 라인센서를 ESP32에 연결한 뒤 ESP32 단독으로 데이터가 읽히는지 먼저 확인합니다.

5. 센서 결과를 PUPRemote 채널로 전달

원본 데이터를 전부 보내기보다 로봇이 필요한 값만 줄여 전달합니다. 예: x 오차, ID, 감지 여부.

6. SPIKE는 제어에 집중

전달받은 특징값으로 PID, 상태기계, 모터 명령, 미션 로직을 수행합니다.

AI vision

ESP32 + HuskyLens + SPIKE Prime

Anton의 PyHuskyLens는 HuskyLens V1/V2와 I2C 또는 UART로 통신하는 Python 라이브러리입니다. ESP32가 비전 결과를 읽고 필요한 값만 PUPRemote로 SPIKE에 전달하는 구성이 특히 실용적입니다.

Anton 예제의 I2C 설정

현재 PUPRemote의 HuskyLens + Pybricks 예제는 ESP32 측에서 SoftI2C를 사용해 SCL=GPIO20, SDA=GPIO19로 설정합니다. 보드 버전/배선에 따라 핀은 달라질 수 있습니다.

ESP32 example SCL = GPIO 20 SDA = GPIO 19 HuskyLens 설정 Protocol Type = I2C
LMS-ESP32 — HuskyLens 라인 추적 결과를 SPIKE로 전달
from machine import Pin, SoftI2C
from pupremote import PUPRemoteSensor
from pyhuskylens import HuskyLens, ALGORITHM_LINE_TRACKING
import time

# SPIKE와 연결
pr = PUPRemoteSensor(power=True)
pr.add_channel("line", "hhb")
pr.process()

# HuskyLens 부팅 대기
time.sleep(4)

# Anton의 현재 예제 핀
i2c = SoftI2C(
    scl=Pin(20),
    sda=Pin(19)
)

huskylens = HuskyLens(i2c)

print("HuskyLens connected:", huskylens.knock())

huskylens.set_alg(ALGORITHM_LINE_TRACKING)
huskylens.show_text("Hello LMS-ESP32 !")

while True:
    lines = huskylens.get_arrows()

    if lines:
        x_head = lines[0].x_head - 160
        x_tail = lines[0].x_tail - 160
        line_seen = 1
    else:
        x_head = 0
        x_tail = 0
        line_seen = 0

    pr.update_channel(
        "line",
        x_head,
        x_tail,
        line_seen
    )
    pr.process()

Communication

PUPRemote · UartRemote · SerialTalk 차이

세 라이브러리는 겹치는 부분이 있지만 목적이 다릅니다. SPIKE의 Powered Up 포트에 '센서처럼' 붙이고 싶다면 PUPRemote가 가장 직접적입니다.

기술핵심 목적주 통신SPIKE 사용 관점추천 상황
PUPRemotePowered Up 센서 에뮬레이션 + RPCLPF2/PUP가장 자연스러움ESP32를 SPIKE 포트 확장장치처럼 사용
UartRemote두 UART 장치 사이의 근실시간 RPCUART별도 UART 경로 필요ESP32/STM32/OpenMV 등 MCU 간 범용 통신
SerialTalkUartRemote 프로토콜의 범용화UART · Socket · BT RFCOMM 등네트워크/무선 확장 가능통신 채널을 UART에 한정하지 않는 분산 시스템

Anton 문서는 UartRemote/SerialTalk을 센서 데이터 약 30–50 Hz 수준으로 읽을 수 있을 만큼 빠른 통신으로 설명합니다. Arduino/C++ 구현은 MicroPython 구현보다 훨씬 빠르지만 배포 난이도는 높아집니다.

Design patterns

자율주행·AI 로봇 수업에 적용하는 방법

ESP32를 붙이는 것보다 중요한 것은 어떤 데이터를 어느 프로세서에서 처리할지 역할을 나누는 것입니다.

A. 센서 전처리형

ESP32: 센서 원시값 수집 → 필터링 → 특징값 계산
SPIKE: 특징값 기반 상태판단 → 모터 제어

예: 8채널 라인센서 → 선 위치/미분값만 SPIKE로 전달

B. AI 인식형

HuskyLens: AI 추론
ESP32: 결과 파싱/축약
SPIKE: 행동 정책 수행

예: 얼굴 x좌표와 ID만 전달 → 사람 추적 로봇

C. 원격조종형

Gamepad/BLE: 조이스틱 입력
ESP32: BLE 처리
SPIKE: 조향·구동 모터 명령

D. 하이브리드 상태기계

ESP32: 복합 센서 이벤트 생성
SPIKE: SEARCH → TRACK → AVOID → STOP 같은 상태 전환

Troubleshooting

수업에서 자주 막힐 지점

1. 펌웨어와 예제 버전 불일치

오래된 블로그 예제의 핀/라이브러리 버전을 그대로 복사하지 말고 현재 firmware installer와 GitHub 예제를 먼저 확인합니다.

2. 통신부터 분리 테스트

센서 + ESP32 + SPIKE를 한 번에 디버깅하지 않습니다. ESP32 단독 센서 테스트 → PUPRemote 더미 통신 → 통합 순서가 좋습니다.

3. 너무 많은 데이터를 보내기

이미지/긴 배열 대신 제어에 필요한 특징값만 보냅니다. 패킷 크기와 루프 주기에 여유가 생깁니다.

4. 블로킹 루프

ESP32 측에서 센서 읽기나 계산이 너무 오래 걸리면 p.process() 호출 주기가 느려져 허브 통신이 불안정해질 수 있습니다.

5. 전원·레벨 확인

외부 센서/서보 전류가 커지면 전원 문제가 통신 오류처럼 보일 수 있습니다. 센서 전압과 GND 공통 여부를 확인합니다.

6. 핀맵 고정 관리

LMS-ESP32 버전과 예제에 따라 GPIO 배치가 달라질 수 있습니다. 수업용 장비는 보드 버전·핀맵·펌웨어를 세트로 문서화하세요.
